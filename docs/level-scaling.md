# 等级缩放公式（已解出）

## 1. 公式

```
F(major, minor) = 1.05 ** min(major - 1, 3)
                * 1.10 ** max(0, major - 4)
                * c(major) ** minor

c(major) = C_LO = 1.008293  (major <= 4)
         = C_HI = 1.010000  (major >= 5)

HP_display  = floor( baseHP  * F )       # 向下取整
DPS_display = round( baseDPS * F, 1 )    # 保留 1 位小数
```

### 两段结构

| major 段 | 每大级步长 | 每小级步长 |
|----------|-----------|-----------|
| 1 → 4 | ×1.05 | ×1.008293 |
| 5 及以上 | ×1.10 | ×1.010000 |

**两段共用同一个拐点 `major 4 → 5`。**

`C_LO` 由实测区间 `[1.0082850, 1.0083140]` 锁定，`1.01^0.83 = 1.0082930`
落在区间正中。`C_HI` 被锁到 `[1.009990, 1.010010]`，即精确的 `1.01`。

## 2. 基础值

```
baseHP  = combatantTuning.health * squadTuning.waveSize

baseDPS = damage * damageToDpsMultiplier
          有 reloadTuning:  damageToDpsMultiplier = clipSize*waveSize / reloadTimeMs * 1000
          否则:             damageToDpsMultiplier = numToBurst*waveSize / cooldown
                            （muzzleStrategy == "All" 时再 × muzzleCount）
```

`waveSize` 在**除法之前**就并入分子，所以不存在"单员 DPS 先取整"的机会。

来源：`gameplay/tuning/CombatTuningInfo.lua`
- `GetHealthInfo`（331-341 行）
- `TryGetBaseDps`（~660-718 行，`reloadTuning` 分支在 705-706 行）

## 3. 为什么 HP 是 floor 而 DPS 不取整

`CombatTuningInfo.lua` 两条路径唯一的差别是**最终转换**：

```lua
local squadBaseHealth = Fixed32(health * waveSize)                        -- 331 行
current = nRankedStatsUtil...ForRankLevel(..., squadBaseHealth):toInt()   -- 336 行  截断
current = nRankedStatsUtil...ForRankLevel(..., baseDps):toFloat()         -- 357 行  保留
```

- **HP** 走 `:toInt()` → 系统性 `≤ base×F`，偏差上界 `0.5/(base×F)`。
- **DPS** 走 `:toFloat()` → 与 `baseDPS×F` 在 1 位小数上一致。

13 个 `waveSize == 1` 观测点上，`F_obs = obs/base` 与理论 `F` 的比值
全部落在 `0.99948 ~ 0.99999`，且**全部**满足 floor 的量化包络，
无一点高于理论值——这是向下取整的签名（四舍五入会双侧散布）。

## 4. 取整时机

**只在链条最末端一次 `floor`**，中间全浮点。7 个候选时机的命中对比：

| 取整时机 | 命中 |
|---|---|
| **末端 `floor(base*F)`** | **28/28** |
| `F` 进 Q16.16 后末端 floor | 28/28（该精度下量化无影响） |
| `base` 进 Q12 后末端 floor | 28/28（同上） |
| 每兵 floor 再 ×waveSize | 17/28 |
| 分步 round | 9/28 |
| 分步 floor（每大级/小级各一次） | 2/28 |
| 每兵分步 floor 再 ×waveSize | 1/28 |

提前取整一律更差。

## 5. 伤害/血量不在「小队成员」上逐员结算

- **DPS 侧**：`waveSize` 在除法前并入分子（见第 2 节）。实测也否定成员优先：

  | 模型 | 全部 19 点 | 小队 15 点 |
  |------|-----------|-----------|
  | **直算 `damage×(burst×wave)/cd`** | **13/19** | **9/15** |
  | `wave × round(单员DPS)` | 1/19 | 1/15 |
  | `wave × floor(单员DPS)` | 1/19 | 1/15 |

  `robodogs`：单员 `22/1.7 = 12.94`，`floor→12` 给 `89.5`，`round→13` 给 `96.9`，
  实测 `96.5`——两个都不对，直算 `51.7647×F` 精确命中。

- **HP 侧**：`robodogs` 的每员值是 `559.25`、`564.75`、`900.75`（**非整数**），
  所以不是"每员整数再求和"。但存在**等价形式** `HP = waveSize × V`，
  `V` 为每员整数——用该形式反解 `health`，`robodogs`(5 点) 与 `riflemen`(2 点)
  各自独立收敛到 JSON 的整数值（见第 7 节）。

- `F` 作用在「每次攻击伤害」上与作用在末端**数学等价**：
  `(d·F)·n·w/cd = d·(n·w)/cd·F`。实测确认（两者同为 9/15）；
  若在 `d*F` 处插入取整则降到 2/15。

## 7. 强约束（区间交集收敛到整数）

用 `HP = wave × V`（`V` 为每员整数）反解 `health`：

| 单位 | wave | 反解 `health` 交集 | 区间内整数 |
|------|------|--------------------|-----------|
| robodogs | 4 | `[299.8337, 300.0366)` | **300** |
| riflemen | 5 | `[129.8028, 130.1108)` | **130** |

各单位的多个观测点独立收敛到 JSON 里的整数值。

## 8. 尚未确定

- **major 2 与 major 7 零观测**，两段结构在拐点处的行为只由 major 1/3/4/5/6/8 支撑。
- `C_LO = 1.01^0.83` 的指数 0.83 尚无解释。实测区间为
  `[1.0082850, 1.0083140]`，`1.01^0.83` 落在其中；`1.008`（整数 0.8%）
  在区间外（差 0.00007），会错 2 个点。
- `GetRankedStatExponentialForRankLevel` 的定点实现未反解出来
  （`libapp.so` 里只有 Lua 注册转发函数，真正实现在别处）。
- 稀有/史诗的等级上限未知（普通/稀有/史诗起始等级分别为 1-0 / 3-0 / 5-0）。
